A separate panel on purpose: these run six orders of magnitude below the computor burns, so a shared axis would hide them entirely. Names come from the registry Qubic publishes for the official explorer, so a newly deployed contract appears by name on its own; an index that registry does not list stays an index.

Where these numbers come from

The official counter (/v1/latest-stats → burnedQus) is cumulative and authoritative, but it is an epoch aggregate: measured over 375 ticks it did not move by a single QU. So a per-day series cannot come from it. This project counts the burn events themselves from a Bob node's tick logs and reconciles the sum against the official counter at every epoch boundary — that ratio is the coverage figure above. Where coverage falls below 100%, a burn category exists that this scan does not recognise yet, and it is reported rather than hidden.
